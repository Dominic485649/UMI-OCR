## 二、为什么仍需 Qt 与 OpenCV，以及实际裁切路线

- **Qt 是主程序的直接依赖**：界面由 Qt/QML 驱动，离线 Markdown 的公式、表格、图片和代码富预览使用 QtWebEngine。不能通过删除正在使用的富预览功能来声称该依赖不需要。
- **OpenCV 也是直接依赖**：图像解码、颜色转换、翻转/旋转等操作不只存在于 OCR 推理插件中。
- 实际绑定是 **PySide6/Shiboken**，不是 PyQt。最终交付优先复用官方 pip 的 PySide6、Shiboken、Qt 6.11.2 二进制，按真实闭包进行文件级投影，不以整套源码重编作为未经验证的硬前提。
- OpenCV 已采用固定来源的最小模块派生构建 `4.10.0.84+umi.coreimg.1`，未保留不需要的 FFmpeg 视频后端。其它 Python 包、可选后端、Qt 模块/插件/QML/资源等按实际闭包裁切。
- PaddleVL 的标题重组确实使用 `sklearn.cluster.KMeans`，因此不能把 SciPy、scikit-learn、joblib、threadpoolctl 整包当作无依赖删除。
- 插件仍保持私有依赖和独立安装/卸载边界；没有靠依赖宿主私有 NumPy/Paddle、删唯一模型、量化或缩减语言/精度/GPU 支持来制造体积收益。
