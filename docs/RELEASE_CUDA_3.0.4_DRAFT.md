# Umi-OCR CUDA 插件 3.0.4（待审稿）

状态截点：2026-10-24，实现及本地候选准备阶段，尚未正式发布。

本次只更新 CUDA 插件，配套本体继续使用已发布的 Umi-OCR 3.0.3，不要求两者产品版本号相同。此文件在实现准备阶段创建，不表示候选构建、启动验收或公开发行已经完成；实际结果以本轮外置验收记录和最终交审文案为准。

## 修复内容

修复 Windows 使用非 UTF-8 原生代码页时，中文安装目录中的 CUDA 模型加载可能失败的问题。已确认的旧版故障表现为 Paddle 初始化阶段的 `[json.exception.parse_error.101]` 和 `attempting to parse an empty input`。

插件改为使用从项目源码编译的专用 worker 入口，在实际加载 Python、Paddle 和模型的同一进程启用原生 UTF-8 代码页；继续使用独立 worker 与 JSON-lines 通信。不是只修改 Python 标准流，也不是仅修改外层主程序。

- 不修改 Windows 全局区域或编码设置。
- 不修改原版 Python EXE，不搬迁模型目录。
- 本体启动器、运行时和业务功能保持 3.0.3；插件自身版本为 3.0.4。
- 模型、精度、CUDA 12.6、Paddle 与依赖锁不升级，不下载新权重，不提供 CPU 静默回退。
- Host API 兼容范围保持 `>=2.7,<3.0`，宿主 API 2.8 不变。

## 安装范围

使用已发布的 3.0.3 基础包，再将 3.0.4 CUDA 插件完整解压到同一应用根目录，保留插件独立的 LICENSES、对应源码和来源记录。建议新目录安装，不覆盖正在运行的旧程序。

专用入口的原生 UTF-8 机制要求 Windows 10 1903+ 或 Windows 11，并需要兼容 CUDA 12.6 的 NVIDIA 显卡及驱动；无需另装 Python 或系统 CUDA Toolkit。发布前须由实际候选确认兼容边界，不能把只在本机通过当作所有 Windows 版本均已验收。

## 本轮验收范围

按维护者指定范围，仅执行启动相关回归：实际进程原生代码页、UTF-8 标准流、CUDA 自检、五个模型初始化、正常停止及退出，并覆盖英文与中文含空格安装目录及代码页 936/65001 的父进程对照。
