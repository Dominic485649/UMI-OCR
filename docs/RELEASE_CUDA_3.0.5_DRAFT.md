# Umi-OCR PP-OCRv6 CUDA 插件 v3.0.5

> 独立插件 Release 文案审阅稿，尚未发布。主程序仍使用已经通过的 v3.1.1 文案；本稿不替换或改写该文案。

## 交付内容

PP-OCRv6 CUDA 为 Umi-OCR 提供离线 GPU 文字识别。插件独立版本为 **3.0.5**，不为与主程序 3.1.1 对齐而升版；清单声明的 Host API 兼容范围为 **`>=2.7,<3.0`**，本次配套主程序的 Host API 为 **`2.8`**。

- **独立 worker 进程。** 由 `UmiOCR-CudaWorker.exe` 运行 GPU 推理栈，主程序通过 JSON-lines IPC 传递图片路径或字节并接收结果；宿主不直接导入 Paddle 推理模块。
- **CUDA-only。** 需要兼容 CUDA 12.6 的 NVIDIA 显卡和驱动。设备、模型或必要依赖不可用时明确报错，不静默回退 CPU。
- **离线模型与 Stored 封装。** 沿用既有 PP-OCRv6_medium、方向分类和 UVDoc 离线输入；选定的 Python 依赖源码收纳于 `vendor.zip` 的 ZIP_STORED 容器，原生库、必要资源和模型仍独立存放，不在启动时整体解包。
- **独立对应源码。** 包内保留本插件自己的 canonical `source/`、源码快照、构建与依赖锁、原生 worker 源码、适用许可证和来源材料。插件的源码及许可记录位于独立命名空间，不覆盖基础程序的同名材料。

**修复预热参数传递。** 后台预热保留已选择的设备、预处理线程及任务类别，避免同一配置在正式识别时再次启动 worker，并避免批量图片或文档预热被错误按截图配置处理。

本次仅修改 CUDA Python 适配器的预热逻辑；原生 worker、依赖和模型保持原字节，不下载新模型、不调整权重或量化精度。新候选另行生成对应源码与实际验收记录。这不是推理引擎或模型质量升级公告，也不宣称整体启动性能得到稳定提升。

## 下载与安装

插件附件：`Umi-OCR-Plugin_v3.0.5_Windows_x64_CUDA.tar.xz`。

配套基础程序：`Umi-OCR_v3.1.1_Windows_x64.tar.xz`，在[主程序仓库](https://github.com/Dominic485649/UMI-OCR/releases)独立发行。基础包不含 OCR 推理插件；本次公开附件不包括 CPU 或 PaddleOCR-VL 插件。本地使用的 PaddleOCR-VL 3.1.1 不表示已获本次公开分发许可。

1. 正常退出旧程序，将基础包完整解压到全新目录。
2. 将 CUDA 插件完整解压到同一应用根目录，保留 `UmiOCR-data/plugins/win32_PaddleOCRv6_CUDA/` 及 `LICENSES/plugins/win32_PaddleOCRv6_CUDA/` 的相对路径。
3. 从根目录的 `Umi-OCR.exe` 启动。运行环境随程序与插件提供，无需另装 Python 或系统 CUDA Toolkit。

`.tar.xz` 有 xz 和 tar 两层。若工具先生成 `.tar`，须继续解包；不要只复制启动器，也不要省略许可证或对应源码。旧配置迁移前保留原件，不覆盖运行中的目录。
