# 可选文档解析 UI 解锁

本功能只区分官方界面的展示，不是文档引擎、HTTP 接口或模型的授权开关，也不承诺防破解。

## 默认行为

- 本体及 CUDA、PaddleVL 插件归档默认不含解锁 DLL。
- 没有有效 DLL 时，PaddleVL 的“文档解析”任务页面、相关页面控制器、预览与页面内任务操作不展示；旧标签恢复和控制器入口也检查同一能力。
- PaddleVL 的 `document` 能力及 `/api/document/*` 保留；模型服务、HTTP 启用开关、监听地址和鉴权沿用原配置，不自动开放网络服务。
- 共享模型/服务设置与图片 OCR 保留；HTTP 所需的版面模型路径、设备和后端参数仍可配置，不因任务页隐藏而删除。普通批量文档 OCR、CUDA 和其他插件页面不受此开关影响。

## 使用位置

将一份受信任的 `Umi-OCR-UIUnlock.dll` 放在 `Umi-OCR.exe` 同目录，然后正常退出并重启程序。不要放进任意插件目录，不需要给 CUDA / PaddleVL 各放一份。

宿主只从上述固定绝对路径检测，不接受 PATH、当前工作目录、环境变量或设置文件里的替代 DLL / 解锁布尔值。链接、硬链接、重解析点、过大文件、未知内容、加载失败或不支持的 ABI 只使相关 UI 保持关闭，不禁用 HTTP 后端。

当前信任采用核验产物的 SHA256 固定绑定：更换 DLL 字节需要由对应宿主版本接纳新的哈希。相同的已信任 DLL 可供保持该 ABI / 信任记录的后续本体与两个独立插件共用，不要求组件版本号相同。

## 公开接口契约

- 平台：Windows x64；DLL 独立版本从 1.0.0 开始。
- ABI：1，C 链接、cdecl，一个 uint32 参数和一个 uint32 返回值。
- 导出：`UmiUiUnlock_Query`。参数是请求的 ABI，返回能力位；ABI 1 的位 0 表示 `structured_document_ui`；宿主策略将该能力关联到 PaddleVL 文档任务页。
- DLL 不实现 UI、模型、HTTP、存储或网络操作；不跨边界传递 STL、分配器、异常、对象、回调或线程。
- 宿主在共享读句柄保持期间核验内容后加载，仅搜索 DLL 所在目录与 System32；安装目录应是可信的本地普通目录。
- 结果在进程内缓存，模块持有至退出，不支持运行中热插拔或卸载；当前任务和共享服务不因 UI 开关而切换/中断。

## 源码与分发边界

宿主门控、页面与 HTTP 的源代码仍按既有许可证和对应源码流程交付。私有 DLL 的实现源码与私有构建材料仅保存在本项目 `build/private/ui-unlock-v1`，按用户要求不进入 Git、源码快照或发布附件；不是可清理缓存。

默认归档不夹带解锁 DLL，其二进制单独交付。没有机器绑定或联网授权：有效 DLL 可复制；修改开源客户端或自行调用 HTTP 仍能使用原引擎能力。

单独 DLL 文件本身并不能决定与 AGPL 组合的许可关系。私有源码不公开按用户要求实施，但闭源 DLL 的公开分发兼容性仍需独立审查；本地构建/测试通过不代表该许可门禁或 GitHub 发布门禁已放行，也不增加模型或商标再分发授权。
