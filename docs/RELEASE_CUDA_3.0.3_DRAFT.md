# Umi-OCR CUDA OCR 插件 v3.0.3：配套本地候选（R2 待验收/待审）

> 本地候选 Release 草稿，不是发行完成公告。含最新修复的 R2 须重建并验收，再交用户审查。当前尚未创建 `v3.0.3` 公开标签或 GitHub Release；没有可据本稿宣称已发布的 3.0.3 下载或哈希。

本插件为 Umi-OCR 提供 PP-OCRv6_medium 离线 GPU OCR。产品版本与主程序保持 **3.0.3**，配套合并 3.0.2 的动态批量队列、导入、忽略区域、输出收尾与设置修复，以及旧源码原地刷新工具停用。本轮还修复从组合候选生成 CUDA overlay 时的对应源码来源选择，不再混用宿主与插件源码；识别引擎、模型、推理精度和依赖均未升级。主程序实现与验收边界见 [3.0.3 主程序草稿](RELEASE_3.0.3_DRAFT.md)。

实际 R2 程序、插件和两份 Release 文案须先由用户审查，明确同意后才推送；公开发行另须通过相应门禁。一般发布请求和对 HDR 功能正确的确认不等于本轮 R2 的审查同意。

## 本轮修复：组合候选的插件源码隔离

- 从组合候选生成 CUDA overlay 时，必须使用插件自己的对应源码、版本、快照和 provenance（来源记录），不得混用宿主材料。
- 不再回退到宿主根目录，避免将宿主对应源码封装成 CUDA 插件源码。
- 旧组合候选缺少明确插件来源时应拒绝并要求重新装配，不从宿主或其它位置自动猜源；不能仅改名、补填版本或沿用旧来源记录来继续导出。

以上是构建封装来源的修复，不是识别引擎、模型、推理精度或依赖升级；产品版本仍为 3.0.3。

## 版本与安装

| 项目 | 3.0.3 准备范围 |
|---|---|
| 插件产品版本 | 3.0.3，与主程序同步 |
| Host API 兼容范围 | `>=2.7,<3.0`；不因产品版本变化而改为 API 3 |
| 平台与依赖 | Windows 10/11 x64，CUDA 12.6；Python 3.13.16，依赖锁不变 |
| 推理方式 | 独立 CUDA worker，按需加载，不静默回退 CPU |
| 模型 | 沿用既有离线输入，不改模型 URL、模型字节或量化精度，不下载新权重 |
| 公开范围 | 基础程序与 CUDA 插件；不含 CPU 或 PaddleOCR-VL 插件 |

本版候选就绪后，先完整解压匹配的基础程序，再将插件完整解压到同一应用根目录。保留 `UmiOCR-data/plugins/win32_PaddleOCRv6_CUDA/` 和 `LICENSES/plugins/win32_PaddleOCRv6_CUDA/` 的相对路径，插件许可证和对应源码不得覆盖主程序的同名记录。

需要兼容 CUDA 12.6 的 NVIDIA 显卡与驱动。运行环境由包内提供，不需要另装 Python 或系统 CUDA Toolkit。CUDA、模型或必要依赖不可用时明确报错，不以 CPU 执行冒充 GPU 成功。

`.tar.xz` 必须完整解开外层 xz 与内层 tar。使用新目录安装，不覆盖运行中的旧程序。旧候选源码原地刷新工具已经停用，新版运行载荷、对应源码和来源材料须一并重新构建，不能用旧包替换源码或改名来冒充 3.0.3。
