# Umi-OCR 3.1.2／PaddleVL 3.1.2 发布文案草稿

本轮仅准备 Windows x64 本地候选，尚未公开发布。实际候选程序、归档摘要、验收结果、未验收限制及清理预演另附本次审查记录；用户对当次程序和文案明确同意前，不推送 main、发行标签或 GitHub Release。

## 独立组件

| 组件 | 本次版本 | 交付方式 |
| --- | --- | --- |
| Umi-OCR 纯本体 | 3.1.2 | 新构建，不内置推理插件 |
| PaddleVL 插件 | 3.1.2 | 前序修复已完成新构建；本次复用已核验归档，需要本体 3.1.2／Host API 2.9 |
| PPOCR／CUDA 插件 | 3.0.5 | 不修改、不升版、不重建，复用已核验的最终归档 |

组件不要求同版；兼容性依据 Host API 声明和实际组合运行，不以版本号一致代替测试。CUDA 3.0.5 声明的 `>=2.7,<3.0` 包含 Host API 2.9。

## 本次更新

- PaddleVL 文档解析默认通过 `/api/document/*` 提供，不展示文档任务页；不改变 HTTP 的启用、监听或鉴权配置，也不影响 CUDA、图片 OCR 或共享模型设置。
- 修复图片右键菜单出现背景却没有文字或动作的问题，以及跨 Python/QML 空序列被错误显示为 `[]` 警告的问题。正常完成通知仍遵循原设置，不全局关闭。
- 区分真实识别分数、合法零分与模型不提供置信度。PaddleVL Spotting 明确显示能力说明，机器结果继续保持未知分数为 null，不制造百分比。
- 任务运行时可以选择目标模型；已接纳任务仍用原模型和参数，安全收尾后自动切换。连续选择以最后一次为准，OCR/document 串行应用，只更新发生变化的能力；显式绑定后端的 HTTP 任务不被 GUI 选择重写。
- 修复文档版面框在 PDF 不同渲染比例、图片 DPI／方向和预览像素尺寸下的映射；不重复叠加视图缩放。部分完成结果显示具体原因。
- 修复跨页重组将同一图片块再次格式化成两张图片的问题，同时保留不同块／页合法重复使用的图片和官方重组顺序；补齐重组后资源名变化的映射。
- 全程序结果 UI 统一 Markdown，提供合并与逐图文件；旧 TXT 配置一次性迁移。HTTP 显式 TXT 请求仅作为兼容层，返回与 Markdown 相同内容的 `.md.txt`；`txtPlain` 是兼容别名。JSON、CSV、PDF 及 HTTP 文本数据字段保留。
- 完善文档结果的 Markdown 渲染，支持标题、列表、表格、官方 HTML 图片、公式、代码高亮／行号、主题和缩放；保留 Markdown 源码、JSON、结构块，复制与导出保持原始内容。默认导出及 ZIP 不再重复附送 TXT。
- 预览完全离线，使用独立匿名 WebEngine profile、受限资产快照和固定渲染壳；禁止任意文件、外网资源、识别内容中的脚本／事件／iframe，外链仍需确认，Chromium 沙箱保留。
- 文档图片与图片 OCR 共用解码能力：JPG/JPE/JPEG/JFIF、PNG、WebP、AVIF、JXL、JXR/WDP/HDP、BMP、TIF/TIFF，并保留 PDF。处理 EXIF 方向、透明白底、高位深归一化；TIFF 保留逐页和选页，其他多帧图片与图片 OCR 一样取首帧。损坏、缺失 codec 和超预算输入明确失败。

## 保持不变的边界

- 资源仍在内部任务目录暂存，导出时复制到结果旁；不改为源文件旁的 `Umi-OCR/文件名/`，也不改名为 pic。
- 不下载、改写、量化或更换用户的 GGUF、mmproj 和版面模型。插件版本升级不代表模型权利或商标使用授权发生变化。
- WebEngine 与必要的对应源码／许可会增加体积；以本次实际包清单报告数字，不用旧包改版本号冒充新包。
- Windows x64 是本轮交付目标；其他平台未构建。用户原始文档未提供，不能声称已直接复测原文档或保证所有文档结果一致。
- 遵循既有要求，截图捕获、HDR 和混屏／多屏测试继续 NOT_RUN，不要求补做。合成图片导入、Qt 页面渲染和 GPU 推理验证不等于桌面捕获。

## 审查与发布

当次审查材料必须列出源码／产物哈希、纯本体无推理插件、归档重装、实际组合运行、已执行的定向检查和具体未执行项。旧版审查同意及旧 PASS 不延用于本次。本地验收后覆盖更新固定安装目录；已有用户配置、日志与任务数据原地保留，不用验收配置覆盖。仅有可原地保留的数据不阻塞程序更新；有实际冲突、进程占用、权限或链接问题时停止相关动作并报告，不覆盖运行中目录、不终止用户进程、不擅自迁移数据或清理兄弟项目。
