## 发行文案草稿

### 设置与启动

- 模型设置集中到全局设置的插件区域，PP-OCR 优先、PaddleVL 在后。任务参数仍使用原 canonical 来源，不复制用户有效配置。
- NVIDIA 设备使用异步下拉发现，显示逻辑 GPU 编号与名称。失效或未发现的设备不被静默替换成 GPU:0。
- PaddleVL 新配置的上下文默认值为 16384，保留已有有效值。默认输出上限仍为 4096，固定全 GPU 卸载策略不等于承诺任意大输出。
- 明确主 GGUF 和视觉投影文件名及官方文件页，不下载或分发 GGUF 模型，不改权重、精度或量化。
- About 的详细平台、CPU 和内存信息改为后台采集。版本和路径立即可用，界面显示等待、失败或取消状态；后台结果在 GUI 线程一次提交。
- 启动观测默认关闭。启用后分别记录环境、Qt、配置、真实首帧、可操作状态和具名后台任务完成，不把首帧等同于可操作。

### 小文件布局

宿主使用 `app.zip` 与 `dependencies.zip`，每个插件使用独立 `vendor.zip`。全部为 ZIP_STORED，保存原始 Python 字节，不压缩，构建时不预编译为 pyc，也不在启动时整体解包。

| 组件 | 聚合原文件数 | 容器数 | 容器大小 |
| --- | ---: | ---: | --- |
| 主程序 | 107 | 2 | app.zip 617399 字节，dependencies.zip 214973 字节 |
| CUDA | 259 | 1 | vendor.zip 3164203 字节 |
| PaddleVL | 1743 | 1 | vendor.zip 9521698 字节 |

这些数字只描述被选输入。未计新清单和 bootstrap 的理论磁盘文件减少量为 2105，不能把所有产品目录的文件差异都归因为聚合。源码交付目录形态与证据文件也会影响完整目录数量。

正常 EXE 仍会为未聚合的外置 Python 模块生成常规缓存，本次发现 138 个、共 2711423 字节。这与构建时不预编译、容器中只保存原始源码是不同边界。缓存已逐项核对对应归档源码、头部和完整嵌套代码对象，没有执行缓存；后续运行仍可能重新生成，干净交付载荷的文件数不是对运行后文件数不增加的承诺。

原生 DLL/PYD、真实路径资源、模型、Qt/QML、dist-info 和许可继续外置。baidubce、networkx、huggingface_hub 等有路径约束的包保持散文件，不为追求文件数扩大白名单。

容器缺失、损坏、未完成、冲突或出现旧布局声明时明确失败，不静默使用旧散文件。成员清单绑定原始源码或独立种子，并保留原 wheel RECORD。

一个 Python 小改动可能需要重拷对应的整个容器。上表同时是当前容器更新量，不能只展示文件数减少而隐藏更新成本。外层搬运格式仍是标准 tar.xz，不是改后缀的 7z。
