# Umi-OCR 深度审查与下一轮优化路线图

审查日期：2026-11-08。基线：`876a3a2332bb311fc568d8db4765278cde3a0bcf`，本轮分支 `audit/ui-docs-3.1.4`。这是全项目分层审查，不是只审最后一次文档提交；也不是“全项目已无缺陷”的证明。

## 结论摘要

项目已有较完整的离线桌面能力、插件 API、共享模型服务、有界任务与资源预算，以及源码／许可／载荷冻结机制。当前主要风险不是缺少另一套 UI 框架或更多抽象，而是**已有边界之间的交接**：父子任务预约与切换屏障、同步状态查询与 GUI、取消／失败终态、外部输入预算、工具链导出与最简分包。

本轮完成任务工作台、设置分组反馈、语言字号，以及直接相关的结果数据保护与标签状态修复；未把 HTTP、模型服务或文档任务架构重写混进 UI 版本。README／docs 按当前事实更新，旧正文与旧图从当前入口退场，必要历史原件保留。

**建议下一轮顺序：先补可确定的并发／失败回归，再处理模型状态与普通文档调度，随后收紧 HTTP／文件边界，最后消除交付工具漂移。** 不宜先增加更多模型、并发或网络开放入口。

完整逐项触发条件、代码位置、现有保护、反证及建议见[发现附录](PROJECT_REVIEW_FINDINGS_2026-11-08.md)。当前候选与最终安装状态分别见[3.1.4 文案](RELEASE_3.1.4_DRAFT.md)和[本地交付记录](LOCAL_DELIVERY_3.1.4.md)。

## 一、范围、方法与证据等级

六个只读审查维度：任务／线程／退出；插件／模型；HTTP／输入／资源；QML／配置／可访问性；原生启动／测试工程；构建／来源／交付／文档。六份发现分别交由三个按领域划分的独立反证组核查，不是声称每条有三票。

原始 **92 条候选**中，85 条得到独立静态确认、6 条仍未证实、1 条为改进。合并三对跨维度重复后为 **89 个原始独立条目**，主线程又补充了按键、Qt 标签恢复、标签移动和失败文档页导出问题。另有本轮 UI／文档／清理质量复核，不能把这些数量相加后称为“全部已复现的 bug”。

| 标记 | 含义 | 不能推导的结论 |
| --- | --- | --- |
| 受控复现 | 真实方法／Qt 组件在隔离输入中表现出错误 | 不等于完整业务、真实模型或所有机器复现 |
| 静态确认 | 调用链、触发条件及缺少保护已被独立核查 | 不冒充运行计时、真实浏览器利用或 native 崩溃 |
| 待验证风险 | 有具体线索，但可达性或后果尚未证明 | 不按已证实漏洞或 P1 故障发布结论 |
| 改进 | 可维护性／可用性／流程收益 | 不混为新回归或已发生的数据损坏 |

主线程以便携 Python 3.13.16、Qt 6.11.2 在无用户数据、无推理、无 HTTP 监听的受控环境，复现了八类问题：非法插件 meta、失败文档页导出、服务状态锁竞争、Qt 标签恢复、历史裁剪选区、删除预算、空选区复制、普通 D 后 Ctrl+D 误清空。基线失败记录原样保留；修复后另开记录。

服务锁复现只证明实际状态方法会等待锁。GUI 同步调用链仍是静态证据，**没有把约 0.188 秒的人为持锁时间当成实际加载模型耗时**。PyMuPDF 多线程、退出排空等未证实项也没有升级成已复现崩溃。

## 二、系统稳定性：优先处理的风险

### A. 模型切换、普通文档和有界调度

1. **LIFE-001，P1 静态**：HTTP 普通文档的父预约等待子 OCR，而模型切换先关闭接纳、等待预约排空，存在循环等待条件。应明确“已接纳父任务派生子任务”的接纳权如何转移，不能只加更长超时。
2. **LIFE-002，P1 静态**：DOC 在有界全局 Qt 池中同步等待同池子 OCR，低容量或占槽条件下可能饥饿。应拆开等待与执行／使用明确续接，而不是无限扩大线程池。
3. **LIFE-003＝PM-001，P1**：GUI 同步服务状态轮询可等待后台模型启动锁。状态读取应返回有限、非阻塞快照，加载和取消留在后台；不得在 QML 定时器回调中等待模型启动。
4. **LIFE-006／007／010，P2**：停止不完整取消子 OCR、普通 GUI 文档未覆盖整任务的模型切换边界、停止同步等待 worker 宽限期。需要同一个可观察的取消／排空协议，避免界面“已停止”而后台继续。
5. **LIFE-008／011／012／013、UI-CONFIG-06..08**：部分结果结算、最后一次预览交接、过期预览和错误终态有缺口。失败／取消／拒绝必须恰好结算一次，不能只屏蔽晚到显示或永久保留加载状态。

**待证而不是已证实**：LIFE-004＝HI-04 的宿主多线程 PyMuPDF 风险、LIFE-005 的退出闭环，需要隔离且有界的测试，不将第三方线程约束直接等同于本机 native 崩溃。

### B. 插件与服务状态

- **PM-002，受控复现**：`meta=true`、字符串和数组等非法类型会抛异常，影响全体插件发现，而不是将单插件标为错误。
- **PM-003／004**：关闭失败仍重置服务注册表，以及插件状态直接截断写入，削弱刷新与崩溃恢复语义。应先保留失败状态，再做原子持久化。
- **PM-007／008／009**：进程退出后的陈旧 ready、配置未匹配的健康状态、vendor／DLL 热刷新残留，都说明“已安装”“进程存在”“模型已加载”“配置匹配”需要明确分开。
- **PM-005／006／010**：下载取消被在途读取延迟、硬链接文件系统限制、嵌套目标目录发布失败。要先固定原子发布与取消契约，再扩展模型下载形式。

本轮不下载大权重、不迁移模型、不选择新的量化精度，也不修改兄弟插件项目。PaddleVL 实现问题只以已安装公开适配层为审查对象。

## 三、HTTP、输入与产物边界

优先级高的两项均为静态结论：

- **HI-01**：`/argv` 用 Bottle 计算 URL 的同源判断受到 `X-Forwarded-*` 请求头影响。需固定可信代理边界和本机来源判定。这里不声称已完成真实浏览器攻击链，现代浏览器的本地网络限制也未做利用验证。
- **HI-02**：100 MiB 目前主要按声明 `Content-Length` 检查，不能覆盖所有 chunked／未知长度传输。预算要放到实际读取流上；不要通过发送超大数据做压力攻击来“证明”。

其它重要边界：

| 组 | 具体问题 | 下一轮最小验收 |
| --- | --- | --- |
| HI-03／08 | JSON 受 4 MiB MEMFILE_MAX 影响；同步等待可用尽 16 个 HTTP 槽位，控制接口也被挤占 | 微小阈值的合成请求与有界槽位 fixture；取消／状态保留可用通道 |
| HI-05..07 | 解码／提图预算太晚；二维码尺寸与滤波核没有统一上限 | 合成尺寸和声明预算，拒绝发生在大分配之前，不用真实大图耗尽资源 |
| HI-09／19 | 并发 CLI 请求共用完成事件；早退泄漏订阅 | 两个具不同 ID 的受控请求及失败早退，结果不得串线 |
| HI-10／20 | 同一文档并发导出互删／截断，任务数上限可超售 | 同任务两次小产物导出和原子任务预约 |
| HI-11／12 | 拒绝任务或重启后输入文件脱离配额／保留期 | 新鲜临时根，拒绝／重启／过期各自有可追溯回收且不碰用户原件 |
| HI-13／14 | CUDA JXL/JXR 衔接与按峰值猜位深 | 按后端的小型格式矩阵、真实 16-bit 数值预期；不以文件筛选器冒充解码成功 |
| HI-15／16 | 本地路径被 URL 解码；保存失败仍报 Success | 含 `%xx` 文件名和明确不可写目标，结果与实际磁盘一致 |
| HI-17／18 | CSV 公式与编码边界遗漏文件名／路径 | 合成公式前缀、非目标编码名称，默认安全与显式原文选项不混淆 |

没有在用户服务或外部目标上做 DoS、并发灌流或利用测试；本轮不自动改变 HTTP 的默认值、用户监听范围或鉴权配置。

## 四、UI、程序简洁性与可访问性

### 本轮已修

- 稳定、无需悬停的任务入口；真实组件版本；模型／插件分组直达，无模型组回退。
- 分组左栏反馈；真实方向键滚动后追踪；窄窗口 Tab 到视口外入口时自动呈现焦点。
- 热切语言同步文字比例；六份实际 QM 编译与七语窗口检查。
- UI-CONFIG-02／04／05／17／19：结果裁剪选区、删除预算、插件旧索引、空选区复制、语言字号。
- MAIN-01..03：Ctrl 双击保护、QVariantList 标签恢复、拖动跨活动页保持所选对象。

实现继续复用 Qt Quick、既有控件、主题、规范配置来源与页面管理，不新增 Web UI、字体下载或第二套配置存储；视觉简化不靠删掉普通 PDF、二维码或插件能力。

### 仍需修复／改进

- UI-CONFIG-01／03／13：同名预览错关联、原生键盘选区与自定义复制索引不同步、销毁后晚到回调；优先稳定 ID 与对象寿命，不再叠加索引补丁。
- UI-CONFIG-09／11／12／16／18／20／21／22：布尔配置键盘可用性、窄表列、建页失败、过长错误框、活动标签落盘、二维码数值约束、Esc 录制和提示键。
- UI-CONFIG-14／15：通用控件可访问名称、通知窗原生关闭后的遮罩属于待证；本轮新入口显式给出可访问名称，不能据此宣称全 UI 无障碍完成。
- 大字号泰米尔语的既有标签省略列为改进，不当成 3.1.4 新回归；可利用空余宽度并提供完整名称提示。
- MAIN-04：失败结构化页进入部分结果后，四种导出均可抛异常。应让失败占位与有效页数据在类型／导出契约上分开。

**简洁性建议**：保留一个共享后端选择源、一条任务接纳状态机和一种稳定页面身份；减少字符串式跨层调用与重复轮询，但不为“代码更短”把错误、预算、许可和回滚分支删除。清理过时代码必须先核对兼容输入与导出契约。

## 五、项目工程与交付

- **DD-01，P1 静态**：CUDA 独立源码导出漏掉当前验证／最简打包入口所依赖的相邻工具。应在导出树内验证实际工具闭包，不只在完整开发仓库检查文件名；这不等于已经证明现有全部公开源码不存在或侵权。
- **DD-02／04..07／09／11／12**：Stored 种子复用、最简门禁参数／父目录、pip 引导位置、旧重装假设、离线源码依赖 Git、临时卷和源码归档命名均有漂移。本轮在具名新目录恢复完整依赖种子，不把绕行说成正式工具已修好。
- **DD-03／EN-07**：对应性漏掉缺失 QML／JS，构建漂移记录未覆盖全部原生输入。本轮保留全输入摘要并另核对原生文件；下一步应让正式门禁同时核对集合和字节。
- **EN-02..09**：原生定长路径、启动失败码、早期错误依赖未挂载容器、旧测试改写安装配置、Qt 白名单测试过时、历史目录／兄弟项目硬依赖，应拆成小的可复现修复。
- **DD-08**：XZ 尾部完整消费是未证实项，需要特定损坏 fixture；不声称已上传归档损坏，也不匿名下载复核已上传附件。
- **DD-10**：旧正式测试入口仍会执行截图，是流程改进；本轮不调用它，不因构建自动扩大全量测试范围。
- **DD-13..17／EN-10**：构建说明、旧单后端 CLI、同步 HTTP 文案、导出根 README 链接、Qt 声明数量和旧 benchmark 需按真实契约维护。已改的 CLI／HTTP 不继续列作未修。

交付过程中另发现 **DELIVERY-001（P1，静态确认）**：旧本地更新引擎跨清单比较未处理Windows大小写别名，可能覆盖原件后回滚丢失。本次更新入口补上叶路径及目录前缀的双重拒绝保护、实际目标解析和已有目标所有权检查，并通过10项定向检查（包含明确标注的其它卷解析模拟）；历史引擎和旧记录不改写，不声称所有旧调用者已修好。后续应将保护收敛进正式更新工具。

### 工程性改进的优先方案

1. 从**导出后的树、安装后的包**运行有界验证，工作仓库和历史 staging 不作隐式补件。
2. 明确编译成功、载荷完整、运行通过、来源许可、用户批准五种状态；一个 PASS 不代替其它四个。
3. 把单机路径、TEMP 和原生输入纳入具名清单；测试使用合成数据，核心离线回归不依赖兄弟仓库或历史目录。
4. 逐步收敛准备、最简分包、归档和恢复的 schema，避免每版都新增只能读取某轮 audit 的脚本；先建小 fixture 保住门禁，不一次重写发布器。

## 八、下一轮可执行路线图
