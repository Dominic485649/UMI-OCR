# Umi-OCR v3.0.2：动态批量队列与文档交互修复

> 待发布文案。当前公开发行门禁未通过，本稿不是发行完成公告。已生成的文件仍为本地候选，不得改名冒充正式包。

本版重点处理[批量文件追加后不继续识别的问题](https://github.com/Dominic485649/UMI-OCR/issues/1)，并补齐批量文档队列交互。当前源码中的实现与完整原生操作验收分别记录，不将未测流程写成通过。

## 更新内容

- **运行中追加进入实际队列。** 批量文档在处理、暂停和保存收尾期间接收新增文件。批量图片 OCR 同样支持追加与续接，单段结束不再等同于整批结束。
- **等待队列可整理。** 文档列表支持拖拽排序和移出队列，真实执行顺序、文档数和页数预算同步调整。正在准备、处理或保存的文档受保护。移除记录不删除磁盘原件或识别结果。
- **导入请求相互隔离。** 打开文件与拖入共用导入路径，支持文件夹和中文、空格路径。加密件保留为待解密，其它正常件继续处理。清空、停止和关闭后的旧扫描结果不会复活旧任务。
- **新增文档行操作。** 右键提供打开原件、打开实际保存产物和单件重新 OCR。重新识别使用独立输出名，失败或取消保留旧成功产物。源码和后端回归已覆盖，完整 GUI 流程仍有下述未验收项。
- **调整忽略区域和预览。** 修复右键绘制状态、数组更新通知、取消、反向拖动和边界裁剪。预览使用当前编辑区域，并隔离旧文档的晚到响应。本轮不宣称完整原生框选流程已经验收。
- **完善输出与退出收尾。** 修复同名独立文本输出覆盖、不同参数任务混用、产物记录重复复制及主线程重复查盘。后台准备与保存采用有界调度，退出时等待输出收尾。
- **修复配置分组折叠。** 使用当前设置对象，并保留原分类、键和值。新增明确加载包内文件的回归，避免用仓库源码掩盖旧包问题。

## 安装与实际验证

先完整解压基础包，再将匹配的 CUDA 插件完整解压到同一应用根目录。保留归档相对路径以及插件独立的许可证、对应源码和来源材料。建议在新目录安装，不覆盖正在运行的旧程序。

基础包本身不含 OCR 推理后端。CUDA 插件使用 PP-OCRv6_medium，需要兼容 CUDA 12.6 的 NVIDIA 显卡与驱动。不需要另装 Python 或系统 CUDA Toolkit。CUDA 不可用时明确报错，不静默回退 CPU。

## 已知限制与发布状态

- Explorer 外部拖放和原生鼠标手势尚未完成验收。完整应用的 Qt 合成事件只验证了部分导入、暂停追加、拖序、移除、页预算、真实执行顺序和原件/多产物路径分派，不能替代原生系统输入或外部默认阅读器验收。
- 合成整轮在单件重新 OCR 菜单定位处超时，总体仍为失败。完整 GUI 重新识别、旧产物哈希保留，以及预览忽略区域过滤和保存返回尚未执行完毕。尚不能确定是测试定位器还是实际界面的原因。
- 完整热配置回归在初始配置应用等待处超时，不能宣称插件切换或界面热配置通过。发布所需的当前源码端到端证明仍缺失。
- 公开 CUDA 门禁中的旧 GPU 回执与当前适配器和运行时锁不匹配。已成功的本地 GPU 运行日志不能替代符合绑定要求的新回执。
- 本轮未完成实际 HDR、混合 HDR/SDR、多屏和完整人工视觉验收，也不继承旧版人工接受记录。
- 旧版配置备份、迁移、旧安装切换及旧版本和缓存清理未执行。新候选目录独立存在，不表示旧目录已替换。

源码更新到 `main` 不等于二进制获准公开发行。公开门禁放行前，不创建正式发行公告，不把本地候选标为稳定版。当前可用的正式下载仍为 [v3.0.1](https://github.com/Dominic485649/UMI-OCR/releases/tag/v3.0.1)。
