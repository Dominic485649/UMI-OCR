# 3.0.2 发布前审查

本记录区分文案准确性、源码公开和二进制放行。审查文案不等于测试通过，更新源码也不等于发行完成。

## 分支与源码范围

- 按维护者最新要求维持 `main`。本地 `main` 已安全快进包含 `release/3.0.0` 的全部更新，没有改名、创建 `master` 或删除分支。
- 当前工作库的 `origin` 属于上游 hiroi-sora，不作为本次推送目标。不将上游历史开发分支当作维护者分支盲目合并。
- 主程序和 CUDA 源码分别沿维护者既有公开 `main` 的过滤快照历史更新。内部开发历史不直接推到公开库，CPU、PaddleOCR-VL、用户配置、助手状态、模型和运行时二进制不在本次源码导出范围。
- 最终标签尚不创建。公开源码提交、内部开发提交和本地候选包的来源是不同层次，不互相冒充。

现有本地候选归档冻结于内部提交 `2a038a48a443140ee3b7f90757e29d72830c094b`。本次文案和源码导出说明的变更不会反向改变旧归档、旧哈希或旧验收记录。

## 公开二进制仍被阻塞

- 两产品的公开源码交付与当前源码端到端门禁尚未放行。不提前创建最终标签，不把本地候选改名为公开包。
- 热配置原始回执没有满足公开自动 GUI 证明。Qt 合成整轮失败不能补作该项成功。
- 托盘本地验证成功，但当版原始回执缺少公开门禁要求的退出前 HTTP 就绪字段。
- CUDA 包内旧 GPU 回执与当前适配器和运行时锁的散列不匹配，需要重新取得绑定当前输入的原始证明。
- 当版实际 HDR 引文、人工覆盖披露及绑定当前源码和载荷的确认材料不完整。旧版人工接受不继承，也不能用一般发布请求替代自动测试证明。
- 此前被权限系统拒绝的私有状态备份与附加热配置诊断没有重做，不换工具或委派绕过。

完整本地原始回执保存在本项目的 `build/audit/3.0.2`，没有因本次公开文案而修改。正式发行需通过原有门禁，另生成与最终公开源码、载荷及归档哈希一致的证据。此前已公开的正式版本仍为 `v3.0.1`。
