# 模型设置更新的资源与输入边界评估

状态：2026-10-26 的实际候选测量。资源可运行不等于识别质量全部通过；本报告不授予公开发布许可。文档坐标边界修复及最终组合验收另留新记录，不改写这里的原始矩阵。

## 本机实测结论

- 测试硬件为 RTX 4060 Laptop GPU，整卡显存 8188 MiB，物理系统内存 33,736,024,064 B，约 31.42 GiB。这不是“8 GB 系统内存”机器。
- 保持原始 BF16 主 GGUF、原视觉投影和版面模型，不下载、不量化、不修改权重。服务为单槽，最大生成长度为 4096 token。
- 已实际加载并执行的上下文配置为 8192、16384、32768。各档均完成普通、密集、长图及选页文档推理，未观察到显存不足或看门狗到期。
- **默认仍建议 8192。32768 只是本轮实际运行到的最高配置，不是硬件或模型的绝对上限，也不证明已填满整个上下文窗口。** 未测试 65536 或 131072；设置控件允许的上限不是本机稳定承诺。
- 增大上下文没有修复本轮相同的密集图误字和坐标偏差。视觉像素、输出长度、上下文、并发槽位及任务总预算是不同限制，不能只调大上下文解决大图问题。

### 本轮整段矩阵的峰值

单位为 GiB，按 2³⁰ 字节换算。下表保留旧成功构建候选 r4 的真实测量，不冒充坐标修复后新候选的复测。

| 上下文配置 | 进程树工作集峰值 | 进程树私有内存峰值 | 整卡显存基线 | 整卡显存峰值 | 驱动内执行耗时 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8192 | 3.87 | 7.85 | 2.33 | 5.20 | 135.40 秒 |
| 16384 | 3.92 | 8.04 | 2.55 | 5.45 | 133.33 秒 |
| 32768 | 4.10 | 8.51 | 2.57 | 5.61 | 124.74 秒 |

测量口径与限制：

- 系统内存列是当时存活的验收进程及其子进程合计，不是整机内存，也不等于可直接相加的模型权重大小。工作集和私有内存不能互换。
- 显存列来自整张物理显卡，包含桌面及其他应用。不同轮次基线不同，不能把峰值或简单差值当成模型净显存。
- 每轮使用相同单槽与输入，但运行时有缓存和桌面状态差异，并存在并行 CPU 构建、装配或哈希工作。耗时只描述本轮执行，不是独占机器的性能排行榜，也不能据此认为大上下文更快。
- 采样间隔为 0.2 秒，未观察到的更短瞬时峰值不能排除。没有在其他显卡、旧驱动、8 GB 或 16 GB 系统内存机器上复测。
- **不能承诺 8 GB 系统内存可运行 VL 文档路径。** 本轮该路径的私有内存峰值已接近或超过这个数量级，系统和其他程序还需要额外内存。

## 当前代码明确执行的输入与任务预算

这些是拒绝或分块边界，不是建议把每张图都扩展到上限。解码像素在分配大图前检查，分块预算仍可能使低于总像素上限的特殊长宽比图片被拒绝。

| 边界 | CUDA 图片 OCR | PaddleVL |
| --- | --- | --- |
| 单文件压缩大小 | 64 MiB | 64 MiB |
| 解码像素 | 64×1024×1024 像素 | 32,000,000 像素 |
| 单边像素 | 50,000 | 32,000 |
| 初始分块数 | 最多 64 | 最多 32 |
| 分块执行保护 | 结果最多 20,000 条 | 含截断再拆分，最多 64 次调用 |
| 分块像素策略 | 检测边长参数限制在 640–8000 | 每初始块最多 1,605,632 像素，并受单边 2048 限制 |
| 选页文档任务 | 旧分页文字 OCR 保持兼容 | 最多 500 选中页，同时受累计 160,000,000 渲染像素限制 |

其他执行边界：

- OCR 任务默认总预算为 300 秒，结构化文档默认 1800 秒；HTTP 请求只能收紧，不可延长全局预算。进度事件不刷新总截止时间。
- GUI、HTTP 和预热共享一个重型执行槽。服务槽位默认单槽，本轮没有测量多槽并发。
- VL 单槽上下文同时容纳视觉输入、提示和生成空间，并留有保护余量。最大输出 token 不能超过该联合预算；控件的独立最大值不代表任意组合都有效。
- 结构化 HTTP 单次上传最多 64 MiB，单任务输出预算 128 MiB，全局任务磁盘预算 512 MiB，单资源最多 16 MiB。每个接纳任务先预留输入、输出与元数据预算，不能把最大任务数量理解为可同时接纳该数量的大文件。
- 旧整页 PDF OCR 在分配前另有单边 32768 和 32 Mi 像素限制，与 VL 的选页渲染路径不是同一个预算。
- 已知截断、区域失败或执行预算耗尽会保留可用结果并报告 partial/warnings。模型没有自行发现的误字或框漂移不能据此自动标成 partial，也不应宣称所有识别遗漏均可检测。

用户最初失败原图未提供，本轮以非敏感可计数合成输入回归，原案例仍未复现。

## 2026-10-27 后续源码设置决定

上述默认建议、测量和质量状态保留为当时记录。用户后续明确要求将新缺省上下文设为 16384，源码清单、插件缺省和 HTTP 预算缺省已对应调整；原有效保存值仍保留，不把旧配置自动改写为新缺省。该后续决定不表示这里的资源矩阵重新运行。

服务和任务的默认最大输出仍为 4096 token。16384 单槽在扣除 2048 视觉及 512 提示预留后，算术预算边界为 13824 token，还需服务与任务输出上限同时允许；它不是实测最大输出。旧图片结果的最大单次实际生成是 1581 token，未触及默认输出帽，未记录完整输入 token，不能宣称测出了窗口或显存极限。
