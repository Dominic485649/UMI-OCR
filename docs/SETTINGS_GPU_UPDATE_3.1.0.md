# 模型设置集中与 NVIDIA 显卡下拉更新

状态：2026-10-27 的源码增量，不是新的正式发行或安装包。当前 `release/Umi-OCR` 和归档没有被本轮源码改动覆盖。主程序、CUDA、PaddleVL 仍按各自独立组件管理，未公开发布。

## 设置变化

全局设置的插件管理区域现在依次展示：插件操作、统一模型设置、PP-OCR、PaddleVL、其他插件。未安装的插件不造占位，已安装但禁用或异常的插件保留开关和原因，仅隐藏其不可用参数。

- 统一模型设置包含模型选择、共享预热、延迟、自动清理和闲置时间。它们仍只有一个全局策略，只预热当前模型，不同时加载两个大模型。
- 截图、批量图片和旧批量文档各自的识别参数也集中到这里，但仍分别保存于原来的 `ScreenshotOCR`、`BatchOCR`、`BatchPDF` 类别，不互相覆盖。
- 任务页面不再重复模型块，快捷键、后处理和输出设置仍在原任务页。即使任务页未打开，中央参数也有唯一来源；关闭或重新打开页面不会销毁参数。
- 删除旧的独立“文字识别”展示组，不删除后端仍使用的 canonical 数据。OCR 和文档的插件参数归入所属插件。
- 当前 OCR 模型的共享服务操作依次是检查服务、预启动服务、终止文字识别任务。没有共享服务的 PP 模型在统一模型设置中保留预热与终止入口。终止仍需原确认，不扩大到文档任务。

## GPU 与模型文件

已有 GPU 文本输入改为 NVIDIA 设备下拉，显示 `GPU:N` 和真实卡名，仍保存 `gpu:N`。它使用当前进程环境下的 CUDA 逻辑编号，不直接采用 `nvidia-smi` 物理编号。设备选择位于各自插件设置末尾。

发现设备在隔离子进程进行，不导入 Paddle/Torch、不加载模型。无卡、驱动缺失、失败和超时有明确状态。刷新不会自动写入第一项，旧失效值保留并标明不可用，只有主动选择有效设备才提交。真实多卡和 MIG 尚未实机验收。

PaddleVL 当前已有的 GPU 字段用于版面检测，不是新增主 GGUF 选卡或多卡分片功能。

GPU Layers 的手动控件已删除，旧键不再参与执行，主模型命令固定全层 GPU 卸载。这里关闭的是手动设置，不是 GPU 加速；CUDA 不可用时仍明确失败，不回退 CPU。

模型提示明确指向官方配套文件：

- 主模型：`PaddleOCR-VL-1.6-GGUF.gguf`。
- 视觉投影：`PaddleOCR-VL-1.6-GGUF-mmproj.gguf`。
- 下载入口：[PaddlePaddle 官方模型文件页](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6-GGUF/tree/main)。

软件不自动下载、改名、修改精度或分发这些模型。提示文件名不替代既有 GGUF 内容校验。

## 上下文、输出和大输入

新的缺省上下文按用户要求调整，已保存的有效值保留，包括旧的缺省值。旧存储不能可靠区分自动落盘默认与显式选择，因此不静默改写已有配置。

| 配置 | 本轮源码行为 |
| --- | --- |
| 新缺省上下文 | 16384 token |
| 服务与各任务缺省最大输出 | 4096 token |
| 单槽视觉和提示预留 | 2048 + 512 token |
| 上下文为 16384、单槽时的算术输出边界 | 13824 token，还需提高服务与任务输出上限 |

上下文容纳视觉、提示及输出，不等于可生成的中文字数。输出预算是每次模型调用的限制，不是整张分块长图或整份文档的总字数。服务上限和任务上限必须同时允许；本轮没有自动提高默认输出。

需要增加输出时，先开启高级设置，在 PaddleVL 的“资源与超时”中提高服务“最大输出 token”，再提高对应 OCR 或结构化文档任务的“最大输出 token”。只提高其中一处不会解除另一处限制；还必须满足单槽上下文预算。额外可调端口、启动与请求超时、并发槽位、Batch/Ubatch 等已有参数。提高并发会分摊总上下文并增加资源压力，不应把它当作提高单次输出的方法。

### 超大图或超多页 PDF 的处理

| PaddleVL 保护边界 | 当前值 |
| --- | --- |
| 单文件 | 64 MiB |
| 解码图片 | 3200 万像素，单边不超过 32000 |
| 初始分块 | 最多 32 块 |
| 含截断再拆分的调用 | 最多 64 次 |
| 文档选中页 | 每任务最多 500 页 |
| 累计渲染像素 | 1.6 亿像素 |
| 图片任务默认总预算 | 300 秒 |
| 结构化文档默认总预算 | 1800 秒 |

长图在有限预算中分块，多页文档先按原页号选页，再逐页处理，不会一次将整份 PDF 填进上下文。高分辨率 PDF 可能在页数上限之前耗尽累计像素或时间预算。

超出接纳边界时明确拒绝。执行中发生区域失败、截断或总预算耗尽时，保留已完成的结果并返回 partial/warnings，不能把部分文字视为全文成功。建议用原页范围分批处理较大文档；本轮没有提高这些安全边界，也不保证能自动检测模型所有误字或遗漏。

验证入口为 `build/audit/settings-gpu-20261027-r1`。定向设备发现、模型中心、通用枚举/折叠、HTTP 预算及翻译检查均已通过。最终真实 Windows Qt 源运行记录 `native-final-r9.json` 为 PASS，覆盖任务参数同源及关闭重开、模型和共享生命周期、终止入口位置、插件禁用恢复、两插件显卡刷新与下拉真实点击、当前七语热切。

本轮还修复了真实 Qt 列表被误判为非共享服务，以及参数来源重载后批量文档组偶发缺失，分别保留失败与修复后的独立记录。原生验收使用新源码沙盒，依赖只读复用当前便携 Python/Qt，不读取或改写用户配置，不启动模型。它不是新包内、归档重装或模型推理验收。真实多卡、MIG 和其他平台不在本轮实机覆盖范围。

历史详细测量见 [资源评估](MODEL_SETTINGS_3.1.0_RESOURCE_ASSESSMENT.md)。旧失败和未测限制不改写，当前 release 安装及原归档仍未替换。
