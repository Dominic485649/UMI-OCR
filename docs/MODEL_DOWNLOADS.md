# PaddleVL 模型获取

适用：支持模型下载的 Umi-OCR 3.1.3 及 PaddleVL 3.1.3 本地候选。旧版本只有手动导入。公开状态以各 Release 为准。

## 下载到哪里

“全局设置 → 插件管理 → PaddleOCR-VL 1.6”中，主 GGUF、视觉投影 GGUF、版面检测模型目录的文件选择按钮左侧均有“下载”。确认框显示模型大小及实际目标位置；网络操作只在确认后开始。

```text
<用户实际安装的软件>/UmiOCR-data/plugins/win32_PaddleOCRVL_1_6/model/
├── PaddleOCR-VL-1.6-GGUF.gguf
├── PaddleOCR-VL-1.6-GGUF-mmproj.gguf
└── PP-DocLayoutV3/
    ├── inference.json
    ├── inference.pdiparams
    └── inference.yml
```

路径由宿主发现的插件真实位置决定，不使用开发目录、当前工作目录推测、系统缓存或写死的盘符。下载目录不可写时明确失败，不提权、不静默换位置。

## 行为与故障

- 后台流式下载，有百分比与取消，不阻塞设置页；取消或失败不会回填半成品。
- 单文件或整组目录全部通过大小、SHA-256 和格式检查后才正式落位并回填对应配置。
- 已有且完全匹配的模型可复用；已有同名但不匹配的模型不覆盖。若需要自行替换，先自行核对并处理原文件，再重试。
- 下载中手动更改了配置，完成时不会用旧请求覆盖新选择。
- 网络超时、证书/服务器错误、空间不足、权限不足均显示原因，可在处理后重新点击。不得关闭 TLS 校验来“修复”下载。
- 不解析网页获取随机模型，不执行下载内容，不接管外部模型服务，不在启动时自动联网。
- 已有外部模型可以继续手动选择，不强制搬迁到 `model/`；主模型与视觉投影须匹配。

PaddleVL 的图片 OCR 需要主模型与投影；完整文档解析还需要 PP-DocLayoutV3。CUDA 插件已包含其配套 PP-OCRv6 模型，不由这些按钮替换。

## 更新与验证边界

更新插件时保留 `model/` 及已有配置。默认运行归档不捆绑本页所列 PaddleVL 权重，用户按需下载或手动导入；需要联网的是获取模型这一步，不是正常离线推理。

自动测试使用有限夹具覆盖流式下载、取消、错误、校验和路径安全。真实官方大权重的完整网络下载是否执行，须在当次验收记录中另行说明，不能把元数据核对或本地已有模型推理记成完整下载通过。
